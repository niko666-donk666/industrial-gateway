## 三、必须背住的固定事实

这些内容需要做到不看代码直接回答。

### 1. 项目定位

STM32负责传感器、OLED、Modbus和实时通信；ESP32负责Wi-Fi、MQTT和JSON上报。两者通过USART2自定义文本协议通信。

### 2. 五个STM32任务

| 任务 | 周期 | 职责 |
|---|---:|---|
| COMM | 10 ms | UART、心跳、ACK、重传、遥测发送 |
| SENSOR | 2000 ms | AHT20、INA219采集 |
| DISPLAY | 500 ms | OLED刷新 |
| MODBUS | 1000 ms | Modbus从机轮询 |
| SUPERVISOR | 500 ms | 任务健康检查和IWDG刷新 |

优先级顺序：

```text
SUPERVISOR > COMM > SENSOR = MODBUS > DISPLAY
```

### 3. ACK机制

- 心跳：`GW,HB,<seq>\r\n`
- 应答：`ESP,ACK,<seq>\r\n`
- 超时：500 ms
- 最大重传：3次
- 首次发送加重传最多实际发送4次
- 重传保持相同`pending_seq`
- 有效ACK条件：格式解析成功、正在等待、序号匹配

### 4. 两把互斥锁

- `s_status_mutex`保护共享状态`s_status`
- `s_i2c_mutex`保护I2C1总线
- 生产任务先准备`sample`再短时间发布
- 消费任务短时间复制`snapshot`，在锁外慢慢使用

### 5. I2C设备

- AHT20：温湿度，地址`0x38`
- INA219：电压、电流、功率，地址`0x40`
- SSD1306：OLED控制器，地址`0x3C`

三个设备可以共用I2C1，但同一时刻只能有一笔总线事务。

### 6. Modbus固定配置

- STM32是主站
- USART1，9600、8N1
- MAX3485完成UART与RS-485电气转换
- 从机地址1
- 功能码03
- 起始寄存器0
- 数量2
- 请求：`01 03 00 00 00 02 C4 0B`
- 校验地址、功能码、字节数和CRC

### 7. 网络链路

```text
STM32文本帧
→ ESP32解析
→ cJSON对象
→ JSON字符串
→ MQTT客户端
→ Broker
→ Topic匹配
→ MQTTX
```

- Wi-Fi获得IP不等于MQTT连接成功
- 有效message_id不等于MQTTX收到
- QoS 1是发布者到Broker至少一次，可能重复
- status使用retain 1；普通遥测使用retain 0
- Last Will用于ESP32异常失联时由Broker发布`offline`

### 8. 已验证与待验证

已经实机验证：

- STM32 FreeRTOS启动
- UART心跳、ACK、500 ms超时、3次重传
- 断线和恢复
- 约39分钟连续运行
- Wi-Fi、MQTT Broker和MQTTX链路

### 9. 三个项目不足

1. UART溢出后只清零长度，没有丢弃到下一换行重新同步。
2. I2C设备启动时缺失后，不会低频重新探测和自动恢复。
3. 异常可观测性不足，只记录IWDG复位，没有完整复位原因、栈高水位和HardFault现场。

## 五、回答项目题的固定结构

任何技术问题尽量按四句话回答：

1. **先给结论**：项目采用了什么方案。
2. **解释机制**：数据或控制怎样流动。
3. **结合项目**：说出对应任务、变量、协议或实测现象。
4. **说明边界**：为什么当前够用，规模变化后怎样升级。

例如“为什么不用DMA”：

> 当前STM32接收的是低吞吐短ACK，所以使用单字节中断加环形缓冲区，已经能把中断收字节和任务解析解耦。现有实机心跳和断线恢复已经验证。它的边界是持续高吞吐时逐字节中断开销和64字节缓冲区不足，如果以后传文件或固件，我会升级为DMA循环接收加IDLE检测。

## 六、遇到不会的问题怎样回答

不要编造。使用以下模板：

> 这一点我目前没有完成实机验证，所以我先区分代码行为和真实结论。当前代码是……；我认为主要风险可能在……；如果让我验证，我会先观察……，再通过……制造对照实验。确认现象后才决定是否修改。

如果完全没有接触过：

> 这部分我没有实际使用过，不能给出确定结论。但结合当前链路，我会先从输入、状态、输出三层确认，再查对应官方文档和日志。

这比猜一个错误答案更像工程师。

## 八、记不住时的训练方法

### 方法一：五张关键词卡

每张卡只写关键词，不写完整答案：

1. 架构：STM32、ESP32、Broker、MQTTX
2. RTOS：五任务、两把锁、sample/status/snapshot
3. UART：中断、环形缓冲区、`\n`、ACK、序号、重传
4. 数据：I2C、Modbus、JSON、Topic、QoS
5. 可靠性：降级、任务健康、IWDG、三个不足

看到关键词后口述，卡住才看答案。

### 方法二：间隔复述

同一个答案分别在以下时间复述：

```text
第一次学习后立即
20分钟后
当天睡前
第二天早上
面试前一天
```

### 方法三：录音而不是默读

每次回答控制在：

- 高频题：30～60秒；
- 项目介绍：2分钟；
- 故障分析：2～3分钟。

录完只检查三件事：

- 有没有先说结论；
- 有没有项目中的具体证据；
- 有没有把未验证内容说成已完成。
