# 问题记录 v1.1：MQTT启动时序

## 记录日期

2026-08-08

## 问题背景

ESP32正式网关固件启动后，UART通信已经正常，但MQTT客户端会在Wi-Fi取得IP地址前尝试连接Broker，导致首次连接失败。

## 问题：MQTT首次连接早于Wi-Fi联网

### 现象

正式固件成功启动，UART初始化正常，但MQTT首先报告DNS和传输连接失败：

```text
Gateway UART ready: RX=GPIO16, TX=GPIO17, 115200 8N1
esp-tls: couldn't get hostname for broker.emqx.io
mqtt_client: Error transport connect
MQTT error
MQTT disconnected
```

数秒后Wi-Fi才成功获取地址：

```text
Wi-Fi connected, IP=192.168.3.123
```

### 原因

原程序在 `app_main()` 中依次调用 `InitWifi()` 和 `InitMqtt()`。`InitWifi()`只启动异步联网流程，并不会等待DHCP完成；紧接着启动MQTT时，设备尚无IP和可用DNS，因此第一次连接必然可能失败。

### 修复方案

1. `InitMqtt()`只创建客户端并注册事件，不立即启动连接；
2. 收到 `IP_EVENT_STA_GOT_IP` 后再调用 `esp_mqtt_client_start()`；
3. 使用 `s_mqtt_started` 防止重复启动客户端；
4. 保留ESP-MQTT自身的断线自动重连机制；
5. 未修改STM32串口、Modbus、传感器数据格式、MQTT主题和QoS配置。

修复后的预期日志顺序为：

```text
MQTT client initialized; waiting for Wi-Fi IP address
Wi-Fi connected, IP=...
MQTT client started after Wi-Fi obtained an IP address
MQTT connected
```

## 构建验证结果

修改后执行独立构建验证，以下步骤全部成功：

```text
Building C object ... app_main.c.obj
Generating ld/sections.ld
Linking CXX executable esp32_gateway.elf
Successfully created esp32 image
Generated C:/industrial_gateway/esp32_gateway/build/esp32_gateway.bin
```

固件大小为 `0xdc7b0` 字节，应用分区剩余约14%。随后使用VS Code总命令完成重新烧录与串口监视，进入正式的 `esp32_gateway` 固件。

## 实机验证结果

修复后的启动日志严格符合设计顺序：

```text
I (783) gateway: MQTT client initialized; waiting for Wi-Fi IP address
I (5313) gateway: Wi-Fi connected, IP=192.168.3.123
I (5313) gateway: MQTT client started after Wi-Fi obtained an IP address
I (5943) gateway: MQTT connected
```

本次结果证明：

1. MQTT初始化阶段不再立即访问DNS；
2. ESP32确认获得有效IP后才启动MQTT后台任务；
3. 从MQTT启动到连接Broker约用630毫秒；
4. 修复后的启动过程中未再出现 `couldn't get hostname`、`Error transport connect` 和首次 `MQTT error`；
5. Wi-Fi首次认证未成功时仍能自动重连，最终连接到路由器并获得固定局域网地址 `192.168.3.123`。

因此，MQTT启动时序修复已通过真实ESP32烧录与联网验证。

## 结论

问题由异步Wi-Fi联网与MQTT启动之间缺少状态约束引起。固件改为“获得IP后再启动MQTT”后，已通过编译、烧录、Wi-Fi联网及MQTT Broker连接的完整实机验证。
